# Agent Note: 模拟器面板改为工作台之上的仪表条

Status: implemented

[English](2026-09-07-simulator-panel-instrument-layout.md) | 中文

## Problem

模拟器页签此前在 framebuffer 上方渲染原生 `<select>`、无样式的 `<button>`、常驻的设备列表和内联的新建表单。其样式表引用了 Moses AI 主题未定义的令牌（`--dsw-space-*`、`--dsw-text-secondary`、`--dsw-accent`），因此每种颜色都回退到硬编码的十六进制值。设备列表与表单占去页签的一半，流只得到剩余空间，而状态行（`Ready`、`Live (h264)`、错误）是散落在按钮之间的普通文本。

## Decision

面板是一台仪器：一条仪表条位于深色工作台之上。

- 仪表条容纳设备选择器（来自 `dsh-client-ui-primitives` 的 `Menu`，行按已启动与已关闭分组、以电源状态为说明文字，页脚为所选设备的启动/关闭以及新建）、一个启动/停止操作，以及带 `StateDot`、状态文本和小胶囊编解码器的读数。
- 新建设备以选择器下方带标签字段的弹出卡片打开，而非常驻表单。
- 工作台在两种主题下均为 `--dsw-static-neutral-bluish-900`，使光栅保持对比度；framebuffer 带细线边框与落地阴影；空、连接中与已停止状态共用一个虚线设备轮廓和一行文案。
- 硬件按钮是设备旁边导轨上的键帽，在流上线前禁用；键盘提示位于其下方，因此没有任何东西遮住屏幕。
- 每种颜色与字体都来自主题别名；面板只以本地自定义属性定义自己的间距刻度与工作台墨色。

套接字、MSE、指针与键盘逻辑保持不变。

## Alternatives considered

**保留页面上的设备列表并仅重设样式。** 被拒绝：面对二十多台模拟器，列表会主导页签而屏幕缩小，观看 agent、手动操作、向客户展示这三种用途都会受损。

**把硬件按钮放在仪表条中。** 被拒绝：它们属于所作用的设备旁边；放在仪表条中会与选择器和读数争夺空间。

**用模态框新建设备。** 被拒绝：模态框会挡住流与聊天；选择器下方的弹出面板让两者都保持可见。

**跟随主题的浅色工作台。** 被拒绝：浅色工作台会降低浅色 iOS 屏幕的对比度，并读作一张空卡片；工作台在两种主题下有意保持深色。

## Consequences

屏幕在每种视口下都获得页签的大部分面积，选择器与读数说明选中了哪台设备以及流是否上线，页签看起来像 Moses AI 原生的一部分。面板现在在运行时依赖 `dsh-client-ui-primitives`（此前已为截图行携带仅类型的依赖）。桥的 `devices` 消息携带每台设备的 `deviceTypeIdentifier` 与 `runtimeIdentifier`；面板按机型对选择器分组，每个运行时一行、最新的在前、已启动的机型靠前，并把芯片标注为 `机型 · 运行时`，因此同一机型在不同运行时上的两台模拟器不再显示为重复项。标签在浏览器中由标识符派生（`device-inventory.ts`），而非通过目录解析，清单仍只需一次往返。

面板仍在 jsdom 覆盖之外（其套接字与 MediaSource 生命周期存在于浏览器中）；此次重设计已通过运行中的 Web 应用对一台已启动的 iPhone 17 Pro 验证：选择器、启动、Live 读数、Home 键帽、停止以及新建弹出面板。
