# Agent Note: DIF Explorer — поверх ограниченного Host Remote как read-only обозреватель рабочего пространства

Status: implemented


[English](2026-08-27-dif-explorer-read-only-workspace-explorer.md) | 中文

## Problem

В Web не было способа увидеть, какие файлы есть в рабочем пространстве, что меняли его сессии или история git и как выглядело изменение, не выходя из харнесса в терминал. Свёртка сохранённых событий `tool/call` даёт состояние «до/после» для правок, которые нигде ещё не закоммичены, чего один git показать не может. Любая такая поверхность обязана быть строго read-only: ограничение путей, argv-allowlist для git, сокрытие файлов с секретами и маскирование содержимого должны жить на стороне Host, чтобы ни один клиентский путь кода не мог изменить рабочее пространство или утечь credential-материалом.

## Decision

Добавлены `@deepseek-ai/dsh-dif-explorer` (Host) и `@deepseek-ai/dsh-client-ui-dif-explorer` (браузер), плюс русская локаль в `dsh-client-locale`. Host-шлюз открывает один read-only Remote-namespace `difExplorer`: корни рабочих пространств из `ctx.workspaceRegistry`, дерево файлов с учётом gitignore, реестр изменений по трём scope (persisted agent sessions свёрткой из логов `ctx.sessionPersistence`, незакоммиченный worktree, недавние коммиты), содержимое файлов по ревизии и unified before→after diffs. Браузерный пакет добавляет одну вкладку `conversation.view` (панели Files / Changes и просмотрщик diff с режимами unified/split, пословным внутристрочным выделением и горячими клавишами навигации по hunk).

`DifExplorerGateway` расширяет `TypertRemoteService` (`namespace difExplorer`) и при каждом вызове заново резолвит корни через `workspaceRegistry`. Доступ к файловой системе проходит через `resolveInsideRoot`, который сначала ограничивает путь лексически (чтобы удалённые пути оставались сравнимыми), а затем сверяет с realpath, закрывая symlink-побеги. Git исполняется через фиксированный allowlist подкоманд (`status`, `diff`, `log`, `show`, `ls-files`, `rev-parse`, `cat-file`, `name-rev`) argv-массивом `execFile` с путями за `--`; всё остальное отвергается до запуска. Записи сессий свёртывают события `write`/`edit`/`str_replace_editor` в записи с размерами фрагментов и числом hunk; `getDiff` принимает либо файловый режим (ревизии base/head через `git show`, сырые байты для детекции бинарности), либо режим tool-call (логированная пара фрагментов). Diff строится jsdiff `structuredPatch` с потолком 5000 строк вывода, деградирует до статистики `--numstat` при сторонах больше 1 MiB и маскирует `.env`/key-файлы и распознанные формы токенов до отправки в сеть. Браузерная половина один раз свёртывает конверты `RemoteResult` в apply-closure, поэтому компоненты потребляют простые промисы; состояние просмотрщика остаётся компонентно-локальным, потому что slot-контракт `conversation.view` не несёт store (тот же паттерн, что у вкладки trajectory).

## Consequences

Поверхность read-only по построению — write-эндпоинтов и возможностей staging/commit/push нет нигде в пакете, поэтому клиентский код не может изменить рабочее пространство или раскрыть секреты. Обязательная верификация: keyless `pnpm exec vitest run packages/host/dif-explorer packages/client/ui-dif-explorer packages/client/locale` (65 package-тестов: модель hunk включая усечение и эвристику бинарности, политика маскирования, ограничение путей со symlink-побегом, wire-парсеры, свёртка сессий, модель дерева/фаззи, сборка split/unified), плюс зелёные `pnpm run lint` и `pnpm run typecheck`. Живая приёмка на `/Volumes/Moses/IT/VideoChain` против реального сервера `dsh web`: `listRoots` отдаёт три корня, `listTree` обслуживает дерево с учётом gitignore, сделанные вручную new/edit/delete появляются ровно в worktree-реестре с корректным diff на +2 hunk, приёмочный коммит виден в commit-реестре с чистыми ISO-временами, зарегистрированные вызовы `edit` другой DSH-сессии попадают в session-реестр с инструментом `Edit` и корректными фрагментами «до/после» в режиме tool-call, файл 1.2 MB деградирует до статистики `oversized`, а `../../etc/passwd` отбивается с `path escapes the workspace root`.

## Alternatives considered

- **Store на view-slot** для состояния «открытый корень / выбранный файл» — восстановление через табу unmount потребовало бы изменения slot-контракта с кросс-пакетным согласованием или runtime-проекции; для первой версии оба вне масштаба, состояние остаётся компонентно-локальным и сбрасывается.
- **Пословный diff на Host** (`diffWordsWithSpace`) — вместо этого лениво исполняется в браузере для каждой видимой изменённой пары (кэш на уровне модуля): обмен небольшим дублированием работы на ограниченные полезные нагрузки.
- **Учёт предсуществования файла в статусах session-ledger** — статусы выводятся только из залогированных аргументов (`write` без старой стороны подразумевает `A`) и не сверяются с фактическим наличием пути; проверять файловую систему на каждую строку реестра признано непропорциональным для read-модели.
