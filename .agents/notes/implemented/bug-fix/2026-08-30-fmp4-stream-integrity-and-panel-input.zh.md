# Agent Note: 端到端的 fMP4 完整性，以及真正驱动设备的面板

Status: implemented

[English](2026-08-30-fmp4-stream-integrity-and-panel-input.md) | 中文

## 问题

模拟器面板能连接、能协商出 h264、能数到数据块——却渲染出一块带解码错误的黑屏。面板提案的 M1 因此没有完成，M2（输入）也没有可落地的表面。对着一台运行中的服务器做实机调试，发现四个相互独立的缺陷叠在同一个症状上，这正是单独修任何一个都毫无变化的原因：muxer 写出的 `trun` box 的尺寸字段停留在零占位符上，浏览器 demuxer 因此拒绝第一个媒体分段；提供方的分块队列在 128 块上限之外丢弃最旧的块，在编码器预热突发下以确定性的方式撕裂字节流；面板的追加路径允许新到的 WebSocket 块超越排队中的块——只要消息任务恰好运行在一次追加完成与其 `updateend` 任务之间，流就被重排（帧中间的字节被当作 box 头，报 `Invalid top-level ISO BMFF box type`）；而播放从不追赶直播边缘，就算管线健康，显示的也是落后整个缓冲积压的旧帧，且处于暂停，没有任何代码重试 `play()`。

## 决策

把 fMP4 当作它本来的样子——一条任何层都不得丢弃、重排或滞后的连续字节序列：muxer 像关闭其他 box 一样关闭 `trun`；提供方队列按字节设界（64 MiB），溢出时大声关闭流，而不是悄悄卸块；面板的追加泵严格 FIFO（每个块都进队尾，追加只取队头）；`holdLiveEdge()` 在每次 `updateend` 上运行，播放落后缓冲边缘超过 1.5 秒就跳到边缘，并重试处于暂停的元素——浏览器会拒绝后台窗格的自动播放，而此外没有任何代码会重试。

在修好的表面上，面板经同一条 socket 驱动设备。指针在画面上的按下／抬起以 8 个 CSS 像素区分 tap 与 swipe，经元素几何换算成设备点（渲染倍率从现售硬件互不重叠的点宽区间恢复——手机 3x 下 250–520 pt、平板 2x 下 500–1100 pt——直到 `describe` 能为几何作证），随后发送 `{action:'input'}`；桥接层校验后对着正在直播的设备调用 seam 的 `input` 动词，正是 seam 文字承诺过的人工驱动路径，不产生任何会话事件。键盘走 USB-HID usage，从 `event.code` 映射，并为省略物理码的派发器提供 `event.key` 回退；带 Shift 的按键把 usage 包进左 Shift 按住序列，单靠 `shortKeyPress` 无法表达。硬件按键以 `{kind:'button'}` 扩展封闭的动作联合类型，词汇取自 substrate 自己的命名（`home`、`lock`、`side_button`、`siri`、`apple_pay`、`play_pause`）。面板把自己限制在 `100dvh − 220px`——因为标签页容器随内容生长而不是约束内容——并把控制行与硬件按键行放在画面上方，收缩只牺牲画面尺寸；全部文案放进 locale 服务后面的 `ru`／`en`／`zh` 词典，状态与错误以键存储，切换语言时连正在显示的状态也会重新翻译。

## 曾考虑的替代方案

**逐层修复、层间验证。** 实际过程正是如此，这也是本记录把四项一起记下的原因：单独任何一项修复留下的都是同一块黑屏，只有叠加后的修复才可观察。分开记录会招来「这个修复没起作用」的反复争论。

**在提供方队列里保留丢弃最旧块的直播语义。** 不予采纳：对整帧编解码（mjpeg）成立，对字节流容器致命。慢到积压 64 MiB 的消费方需要的是重启，不是一条被悄悄破坏的流。

**等 `describe` 为几何作证，而不用倍率启发式。** 最初未采纳，因为 `describe` 会让 helper 崩溃——序列化器无界 AX 递归导致的栈溢出，后来以 `FBAXReadLimits`（深度 50、3000 节点）为界修复。`describe` 可用之后，桥接层在每次流启动后发送已作证的屏幕尺寸，面板优先使用它；区间启发式只作为 `describe` 无法服务时的回退保留。

**单独开一条输入 WebSocket。** 不予采纳：流 socket 本就双向承载带类型的 JSON 控制消息，第二条 socket 只会重复信任栅栏与设备绑定，换不来任何隔离收益。

## 后果

面板成为可用的模拟器：直播边缘的 h264、点按、滑动、打字、硬件按键，全部对着运行中的设备用眼睛验证过（面板点击切换了选中的芯片、面板拖动平移了地图、面板滑动打开了 Spotlight 并用物理键盘输入、Home 回到了主屏）。来自面板的输入不产生 `iosSim/action` 记录，保住了「模型可见 ⟺ 已记录」的边界。代价：`trun` 布局保持单样本；面板的视口上限硬编码了应用外壳的 220px，在标签页容器学会约束子元素之前只能手工跟随外壳布局。

## 测试

对着已启动的 iPhone 17 Pro 上的 `dsh web` 实机验证：线上流做过 box 校验（609 对 moof/mdat，零异常），第一个 `moof` 逐字节检查（`trun` 尺寸 32，正确），随后每一种交互都从面板发起并直接观察设备。四个包 `tsc -b` 全绿；client 与 host 产物均已重建。尚无自动化覆盖：无密钥快照通道无法驱动已启动的模拟器，实机探针脚本仍是会话本地的——桥接层的真实测试缝（mock IosSimulator、录制的 socket transcript）是下一笔测试欠账。
